# BP 卡：聚合设计文档标准（design-doc-template）

> 源：`documentation/best-practices/design-doc-template.md` · 派生时间：2026-10-18 · 框架版本：2.0.0

## 1. 标准定位

聚合设计文档描述「一个聚合如何被设计与实现」，是实现前**唯一输入**与**评审依据**。新建/修改聚合都产出；只定义文档结构，不讲解框架机制（只引最佳实践链接）。

| 场景 | 产出 | 差异 |
| --- | --- | --- |
| 新建聚合 | 是 | 静态模型+行为+规则+事件+持久化 |
| 修改聚合 | 是 | 额外含根因分析 + 改动清单/落地顺序 |

与框架最佳实践区别：设计文档是「这个聚合怎么设计/改」（一次性）；最佳实践/BP 是「框架能力怎么用」（长期稳定）。

## 2. 固定 13 节骨架

章节编号与标题必须一致，便于跨文档定位与自动化抽取：

| # | 章节 | 必选 |
| --- | --- | --- |
| 1 | 概述与背景 | ✅ |
| 2 | 聚合边界与职责 | ✅ |
| 3 | 领域模型静态结构 | ✅ |
| 4 | 状态与行为设计 | ✅ |
| 5 | 业务规则设计 | ✅ |
| 6 | 领域事件设计 | 视场景 |
| 7 | 持久化与仓储设计 | ✅ |
| 8 | 应用层设计 | 视场景 |
| 9 | 接口层设计 | 视场景 |
| 10 | 时序 | ✅ |
| 11 | 改动清单与落地顺序 | ✅ |
| 12 | 测试清单 | ✅ |
| 13 | 风险与待确认事项 | ✅ |

> 规则：第 6/8/9 节按场景选填；其余 10 节恒必选。某节不适用时**保留标题写「本次不适用，原因：……」**，不删节。

## 3. 各节要点

- **结论先行**（顶部引用块）：一句话「选什么方案 + 为什么」；附「本文仅为设计文档，未改动任何代码」。
- **概述与背景**：新建写业务诉求；修改必含**三层根因**（直接原因→深层原因→本质原因，本质落到职责/边界/模型层面）；代码引用统一 `行号:相对路径` 格式可点击。
- **边界与职责**：聚合根是谁+为什么；包含哪些实体/值对象；**不归本聚合管什么**（同等重要）；核心不变量。
- **静态结构**：给可直接编译骨架（真实包名/导入/构造签名）；聚合根/值对象/标识符/枚举。**枚举约定**：出入参/查询条件/Input 的枚举值用 `Integer`/字符串基础类型；投影中枚举转基础类型（见 `enum-value.md`）。
- **状态与行为**：操作/命令清单 + **允许矩阵**穷举「什么状态允许什么操作」+ 边界澄清（明确不做什么）。
- **业务规则**：判定「状态是否被推进过」的前置规则必须明确读**旧快照** `old`（框架 `execute` 先跑领域逻辑后校验，当前态已被改）；写清激活条件（如 `hasOperation`）与新旧读法对应。
- **事件**：表格列事件/携带内容/订阅者/投影影响。
- **持久化与仓储**：表结构 DDL/映射/仓储接口/投影（受影响的读模型，零改动也写理由）。
- **应用层/接口层**：Input/Updater/WriteService 入口；HTTP/RPC/Request/Response；零改动保留标题。
- **时序**：完整执行路径 + 调用顺序约束。
- **改动清单**：表格三列（确切文件路径 + 动作新增/改/删 + 说明），缺一不可；另给**落地顺序**保证每步可编译可单测。
- **测试清单**：期望写确切消息码常量名/状态枚举值（不写「报错」）；标出验收核心用例；区分规则层单测与应用服务集成测。
- **风险**：触发条件 + 应对；顺带发现的同类缺口记风险表标「不在本次范围」，避免范围蔓延。

## 4. 符合性自检（13 项）

结论先行块 / 修改类三层根因 / 边界含「不归本聚合管」/ 可直接编译骨架 / 状态类允许矩阵 / 明确「不属于本设计」/ 前置规则标注读旧快照 / 持久化应用接口层齐全（零改动写理由）/ 改动清单含路径+动作+说明 / 落地顺序每步可编译 / 测试含确切码值标验收核心 / 风险含触发条件与应对且缺口标「不在本次范围」/ 13 节编号标题一致。

## 5. 常见反模式

| 反模式 | 正确做法 |
| --- | --- |
| 只有方案没根因（修改类） | 写三层根因，本质落职责/边界 |
| 边界不清什么都往里塞 | 明确「不归本聚合管」 |
| 代码引用不带路径行号 | 统一 `行号:相对路径` |
| 只正文描述改动无清单表 | 独立改动清单表+落地顺序 |
| 期望写「报错/失败」 | 写确切消息码常量名与状态枚举值 |
| 状态前置规则读当前态 | 前置判断必须读 `old` |
| 基础设施层直接省略 | 保留标题写「零改动，理由」 |
| 顺手一起改顺带缺陷 | 记风险表标「不在本次范围」 |
| 文档重复讲框架机制 | 只给最佳实践链接 |
