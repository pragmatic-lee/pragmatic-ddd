# BP 卡：聚合设计文档标准（三契约 + 一快照 · 流程权威）

> 源：`documentation/best-practices/design-doc-template.md` · 派生时间：2026-10-29 · 框架版本：2.1.0-SNAPSHOT
> 本卡是**交付节奏与回流路径的唯一权威**：闸门、迭代轮次、回流矩阵、一致性校验只认这一份，其余卡片与 skill 只引用。

## 1. 四份文档

| # | 文档 | 性质 | 落盘 | 结束方式 |
| --- | --- | --- | --- | --- |
| ① | 本次需求语义（`bp.design-doc-semantics`） | 契约 | `changes/active/{需求}/{agg}/semantics.md` | 验收后归档 |
| ② | 聚合写设计（`bp.design-doc-write-template`） | 契约 | 同目录 `aggregate-design.md` | 实施后归档 |
| ③ | 投影读设计（`bp.design-doc-read-template`） | 契约 | 同目录 `projection-read.md` | 与 ② 同批归档 |
| ④ | 聚合事实（`bp.design-doc-facts`） | 快照 | `aggregates/{agg}/facts.md` | 永不归档 |

契约回答「这次答应了什么」，快照回答「现在实际是什么」。①②③ 归档整目录移动；④ 从代码推导、覆盖更新。

## 2. 状态与版本戳

| 文档 | 头部必写 | 状态取值 |
| --- | --- | --- |
| ① | `版本：vN ｜ 基线：④ 核对日` | 草稿 / 已确认 / 修订中 / 归档 |
| ② | `基于：① vN（定稿日）+ ④ 核对日` | 待启动 / 草稿 / 待对齐 / 已确认 / 归档 |
| ③ | `基于：② vN + ① vN` | 待启动 / 草稿 / 待对齐 / 已确认 / 归档 |

- ① 升版后 ②③ 自动置「待对齐」，并在 ② §10.2 列出「尚未对齐 ① vN 的哪几条」。
- 状态不是「已确认」不得交棒实施；未归档不得被下一次需求当基线。

## 3. 四道闸门

| 闸门 | 进入条件 | 产出 | 不过闸 |
| --- | --- | --- | --- |
| G1 语义开写 | 需求已给、④ 已读、前置条件已核 | ① 第 1 轮 | — |
| G2 语义定稿 | 用户显式说定稿；附录 C 无「未定」；自检 16 条过 | ① 置「已确认」 | 继续迭代，不越界改用户没提的章节 |
| G3 写设计开写 | G2 已过 **且** 用户点名 | ② | 先问「要出写设计吗」 |
| G4 投影读开写 | G3 已过 **且** 用户点名 | ③ | 先问「查询场景要落成投影吗」 |

- **一次只产一份**：① 未确认不得动 ②③；② 未定稿不得顺手开 ③。
- **②③ 是点单不是默认全出**：① §8 有 Q 只说明「要能被查」；不做时在 ① 或 ② 末尾写一句决定，不靠沉默。

## 4. 迭代轮次（G1 → G2）

| 轮次 | 做什么 | 不做什么 |
| --- | --- | --- |
| 第 1 轮 | 全量骨架（新建）/ 受影响章节 + 基线（迭代）；待确认进附录 C | 不猜业务、不替业务方编查询场景 |
| 第 2..N 轮 | 只改点到的章节 + 连带章节（改动作 → 3.1 / 3.2 / 5.3 / 6.4）；R / Q 只增不改 | 不整篇重写、不重排编号、不美化未触及章节 |
| 每轮汇报 | 三行：改了哪几章 / 新增哪些 R·Q·动作 / 附录 C 还剩什么 | 不复述未改动内容 |
| 定稿轮 | 跑自检、附录 C 逐条处置、状态置「已确认」 | 定稿后不静默改（要改就升版） |

收敛判据：用户显式确认 + 自检通过 + 附录 C 无「未定」。

## 5. 回流矩阵

判别式：**改的是「业务上说得通吗」→ 回 ①；改的是「技术上怎么落」→ 停在 ②③；两句话都沾 → 拆成两件事分别落。**

| # | 在哪发现 | 发现什么 | 回流到 |
| --- | --- | --- | --- |
| B1 | ② | 新增 / 修改业务规则 R | ①（§5） |
| B2 | ② | 新增动作，或动作写入字段变了 | ①（§3） |
| B3 | ② | 事件载荷不够用 | ①（§4.1） |
| B4 | ② | 状态维度或流转条件变了 | ①（§6） |
| B5 | ② | 表结构 / 索引 / TypeHandler / 执行顺序 / 常量 | **止于 ②**（§10.1） |
| B6 | ③ | 需要 ① 里没有的查询场景 Q | ①（§8，编号只增） |
| B7 | ③ | 查询要的字段表里没有 | ① 有属性 → ②；① 也没有 → ① |
| B8 | ③ | 数据同步事件不够用（时机 / 载荷） | ①（§4）+ ②（§5、§6.8） |
| B9 | ③ | 读源 / mapping / REPLICA_ID / TTL / 分片 / 裁剪 / 分页 / 索引 | **止于 ③** |
| B10 | ③ | 业务筛选口径不明 | ①（§8 + 附录 A） |
| B11 | 任意 | 与 ④ 事实不一致 | ④ 记现状 + ① 就地标 `（当前：xxx）` |

两条总则：

1. **上游优先、单一落点**：业务事实只有 ① 一个写入口，下游只提请不改写；②§10.x 是登记台不是修复台。
2. **不跳级**：顺序固定 `① 定稿 → ② 对齐 → ③ 对齐`；① 未定稿就改 ③ 等于在流沙上盖房。

## 6. 一致性校验（交付前、归档前）

1. ① 的 R / 动作 / 事件 / 状态维度 ⊆ ② §1.4 追溯覆盖，且 ② 无 ① 没有的动作。
2. ③ 的 Q 集合 = ① §8（不多不少、编号不改）。
3. ③ §1.2 来源事件 ⊆ ② §5.1 事件清单。
4. ③ §3.1 投影字段 ⊆ ② §7 表结构。
5. 归档前：② §10.6 与 ④ 一致、① 无「未定」、②③ 不为「待对齐」。

## 7. 归档与止损

归档 = 目录移动 `changes/active/{需求}/` → `changes/archive/{需求}/`，三条判据全满足才移动：①②③ 完成、`facts.md` 已更新、② §10.6 已回填。

- **① 升版 ≥ 3 次**：需求本身没定，停手回业务澄清。
- **归档后不回改 ①**：发现遗漏开新需求目录写增量语义。
