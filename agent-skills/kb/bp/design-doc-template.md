# BP 卡：聚合设计文档标准（design-doc-template）

> 源：`documentation/best-practices/design-doc-template.md` · 派生时间：2026-09-19 · 框架版本：2.0.0

## 1. 定位

使用框架的团队/开发者在**新建聚合**或**修改既有聚合实现**前产出的**设计文档标准**。文档只定义「长什么样」，不重复讲解框架机制，仅引用对应最佳实践链接。是评审与实现（人/AI）的**唯一输入**。

## 2. 固定 13 节骨架（章节编号/标题必须一致）

| # | 章节 | 必选 | 回答 |
| --- | --- | --- | --- |
| 1 | 概述与背景 | ✅ | 哪个聚合，为什么，范围 |
| 2 | 聚合边界与职责 | ✅ | 聚合根、包含/不包含、不变量 |
| 3 | 领域模型静态结构 | ✅ | 可直接编译的骨架（含包名/导入/构造） |
| 4 | 状态与行为设计 | ✅ | 操作/命令、状态机允许矩阵 |
| 5 | 业务规则设计 | ✅ | 不变量、何时校验（当前态/旧快照） |
| 6 | 领域事件设计 | 选填 | 事件/载荷/订阅者/投影影响 |
| 7 | 持久化与仓储设计 | ✅ | 表/映射/仓储/投影 |
| 8 | 应用层设计 | 选填 | Input/Updater/WriteService |
| 9 | 接口层设计 | 选填 | HTTP/RPC/DTO |
| 10 | 时序 | ✅ | 一次调用完整路径、顺序约束 |
| 11 | 改动清单与落地顺序 | ✅ | 确切文件路径+动作+顺序 |
| 12 | 测试清单 | ✅ | 确切消息码/枚举值，标验收核心 |
| 13 | 风险与待确认 | ✅ | 触发条件与应对，缺口标「不在本次范围」 |

> 第 6/8/9 节按场景选填；其余 10 节恒必选。不适用的节**保留标题写「本次不适用，原因：…」**，不可删除。

## 3. 关键规则

- 顶部**结论先行**块：一句话结论（选什么方案+为什么）。
- 修改类必含**根因分析**（三层：直接/深层/本质原因，本质落到职责/边界）。
- 代码引用用 `` `行号:相对路径` `` 格式可点击跳转。
- 状态类需求含**允许矩阵**穷举组合，显式写「不属于本设计」边界。
- 前置类规则（仅待发货可发货）必须标注读**旧快照 `old`**（框架先跑领域逻辑后校验）。
- 枚举值约定：出入参/查询条件/Input 用 `Integer`/字符串基础类型；投影读模型同转基础类型，不用枚举类型本身。
- 改动清单三列缺一不可（文件+动作+说明）；给出落地顺序使每步可编译。
- 测试期望写**确切消息码常量名/状态枚举值**，标注验收核心用例。

## 4. 符合性自检（摘要）

顶部结论先行 ✓ · 修改类根因 ✓ · 边界含「不归本聚合管」✓ · 静态结构可编译骨架 ✓ · 状态含允许矩阵 ✓ · 前置规则标读 old ✓ · 改动清单含确切路径+动作+说明 ✓ · 落地顺序每步可编译 ✓ · 测试含确切消息码/枚举 + 验收核心 ✓ · 风险含触发条件与应对 ✓ · 章节 13 节一致 ✓。
