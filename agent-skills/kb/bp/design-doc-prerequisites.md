# BP 卡：实施前置条件（项目级闸门）

> 源：`documentation/best-practices/design-doc-prerequisites.md` · 派生时间：2026-10-29 · 框架版本：2.1.0-SNAPSHOT

## 1. 定位

生成设计文档或代码之前必须由人确认的**项目级技术事实**。与聚合级澄清分工不同：

| 类型 | 例子 | 谁确认 | 频率 | 落点 |
| --- | --- | --- | --- | --- |
| 项目级 | 数据库、事件总线、Outbox 开关 | 技术负责人 / 架构 | 一次，随技术演进改 | 项目前置条件清单 |
| 聚合级 | 某个 Q 走 ES 还是数据库直读、业务待确认项 | 业务方 + 技术负责人 | 每个需求 | 各自设计文档 §10、投影文档 §1.3 |

## 2. 固定 10 项

| # | 前置条件 | 影响面 |
| --- | --- | --- |
| 1 | 数据库类型与版本 | DDL 方言、JSON 列类型、`jdbcType`、生成列语法 |
| 2 | 事件总线（可多选）：RocketMQ / Kafka / ThreadPool | 配置类、topic、订阅装配 |
| 3 | 是否启用 Outbox | 执行器选型、outbox 表、事务边界 |
| 4 | 补偿模式 | 补偿动作实现、compensation 表 |
| 5 | Redis 版本与客户端 | 配置类、序列化方式 |
| 6 | ES 版本与安全开关 | 客户端配置、索引 mapping |
| 7 | ID 生成方式 | 工厂、事件即时 / 延迟判定 |
| 8 | 部署实例数 | 清理、对账并发、补偿幂等 |
| 9 | 时区 | 时间字段口径、跨时区展示 |
| 10 | 多租户 / 数据隔离 | 查询条件、索引、缓存 key 前缀 |

清单字段固定三项：编号 / 前置条件 / 结论。

## 3. 三条硬规则

1. **有结论才算已确认**：结论非空且不是「待确认」。
2. **「待定」不允许跨迭代存活**：迭代结束仍待定的，评审上给结论或明确「不涉及」。
3. **未确认即阻断**：不是提醒，是对应产出不生成。

## 4. 阻断映射

| 未确认项 | 禁止产出 |
| --- | --- |
| 数据库类型与版本 | DDL、Mapper、TypeHandler 装配 |
| 事件总线 | 事件配置类、订阅装配；多选时每种总线各一套装配与 topic |
| 是否启用 Outbox | 执行器选型、outbox 表与装配 |
| 补偿模式 | 补偿动作、compensation 表 |
| Redis 版本与客户端 | Redis 副本、缓存投影、序列化配置 |
| ES 版本与安全开关 | ES 副本、索引 mapping、客户端配置 |
| ID 生成方式 | 工厂、事件的即时 / 延迟判定 |
| 部署实例数 | 清理任务、对账并发、补偿幂等 |
| 时区 | 时间字段口径、跨时区展示 |
| 多租户 / 数据隔离 | 查询条件、索引、缓存 key 前缀 |

## 5. 使用要点

- **可多选项**：事件总线允许同时选多个，结论列写全并说明各承载哪些事件；单选也合法。
- **冲突以清单为准**：设计文档与清单不一致时改文档，不迁就文档。
- **清单只增不删**：新增项写明「为什么它是前置条件」；作废项标「已废弃」保留行。
- **技术升级改清单**：受影响的聚合设计文档打「需复核」标记。
- **使用顺序**：出文档前读清单 → 未确认项进写文档 §10.3 → 生成代码前逐项核对阻断 → 回填解除。
