> 源：`documentation/best-practices/design-doc-write-template.md` · 派生时间：2026-10-29（闸门 / 回流同步） · 框架版本：2.1.0-SNAPSHOT

## 1. 定位

三契约中的第二份，把① 本次需求语义翻译成可实施的技术形态。

| 文档 | 性质 | 份数 | 结束方式 |
| --- | --- | --- | --- |
| ① 本次需求语义（`bp.design-doc-semantics`） | 契约 | 每需求一份 | 验收后归档 |
| ② **写设计（本卡）** | 契约 | 每需求一份 | 实施后归档 |
| ③ 投影读（`bp.design-doc-read-template`） | 契约 | 每需求一份 | 与②同批归档 |
| ④ 聚合事实（`bp.design-doc-facts`） | 快照 | 1 份 | 永不归档，从代码推导 |

落盘：`docs/design/changes/active/{需求}/{agg}/aggregate-design.md`（归档随目录移到 `changes/archive/`），统管横切（改动清单 / 测试 / 风险 / 回填）。

**启动条件**（缺一不落笔）：① 已标「已确认」且头部写了 `基于：① vN`；用户明确点名出写设计（G3）。头部另写 `聚合事实基线：④ 核对日` 与 `状态：草稿 / 待对齐 / 已确认`。

## 3. 关键硬约束

**领域模型**

- 聚合根 `@Getter` + `@Setter(PROTECTED)` + `@NoArgsConstructor(PROTECTED)`；禁 `@Data` / `@EqualsAndHashCode` / `@Builder`。
- 业务方法纯赋值，无 `if + throw`、无数据组装；先 `recordOperation` 后 `collectEvent`。
- ID 构造期已确定用即时事件，未确定才用 `() -> buildEvent(this)`，并写明判定依据。
- 值对象 `extends ValueObject` + `equalityComponents()`；枚举 `implements IEnumValue<Integer, 自身>` + `of()`。

**规则**

- 三组固定：A 全局（总是）、B 准入（`hasOperation(PLACE)`）、C 状态前置（`hasOperation(动作)`）。
- 组 C 全部读 `old`；容器 `requireOldEntity()=true`，`supplyOldEntity` 走仓储 `findById`。
- 覆盖对照列：编号 / 规则 / 消息码 / 组 / 激活条件 / 读取字段（写明 `old.x` 还是当前态）。

**应用层**

- 执行器选型必须有表：`CommandExecutor` / `OutboxCommandExecutor` / `CompensableCommandExecutor`，与工作单元工厂成对匹配。
- 一个工作单元只允许记一个操作；需两个操作的必须拆用例（主操作与回写分开）。
- 订阅登记只登记业务订阅；投影侧订阅归读文档。

**持久化**

- 表边界 = 聚合边界；主表有 `version` + 四审计列 + 软删列；子表不设 `version`；无物理外键。
- 子表差量**先 DELETE 后 INSERT**（合并 / 改数量产生同 id 先删后插）。
- `doUpdate` 判 `affected == 0` 抛乐观锁异常；resultMap 映射 `entityDelete` 到软删列。

**对照与回填**

- 设计增量、语义缺口、业务待确认、框架签名、设计风险、实施回填六类集中在 §10。
- 框架签名只登记不臆造；归档前必须回填 §10.4 与 §10.6。

## 4. 代码形式比例

| 对象 | 给多少 |
| --- | --- |
| 聚合根 / 子实体 / DDL / 注册表 / 装配类 | 完整 |
| 值对象 / 枚举 / 事件 / Input | 1 个完整示例 + 表 |
| 规则容器 | 组 A/B/C 各 1 条示例 + 判定方法，其余按 §4.4 表展开 |
| 写服务 | 1–2 个方法 + 用例差异表 |
| Mapper | 固定 4 片段（resultMap / CAS / 差量 / 删除） |

判定法：不写实施者会写错，就写；只是懒得打，就不写。

## 5. 回流与一致性

发现上游缺东西时按 `bp.design-doc-template` §5 回流矩阵处理，本份只负责**登记**：

| 发现 | 去哪 |
| --- | --- |
| 业务口径（规则 / 动作 / 字段 / 事件载荷 / 状态） | 回 ① 定稿后再对齐；§10.2 记「已回 ① vN」 |
| 纯技术形态（表 / 索引 / TypeHandler / 执行顺序 / 常量） | 就地改；§10.1 记设计增量 |
| 实施偏差 | §10.6，属代码不回流 |

硬约束：① 升版后本份置「待对齐」；不得静默一致化；归档前 §10.2 不得有「未回」。

## 6. 自检要点（18 项，摘要）

生命周期四项齐 / 追溯覆盖全部元素 / 类清单与包布局一致 / 无 `@Data` 与 `if+throw` / recordOperation 先于 collectEvent / 组 C 读 old 且逐条列改写操作 / 执行器选型覆盖全部用例 / 一工作单元一操作 / 差量先删后插 / DDL 三件套 / 测试按消息码 + 组 C 不激活回归 / §10 六小节无空格 / 前置条件已确认。
