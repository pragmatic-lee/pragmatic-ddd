# BP 卡：聚合写设计文档模板（写模型）

> 源：`documentation/best-practices/design-doc-write-template.md` · 派生时间：2026-10-26 · 框架版本：2.0.0

## 1. 定位

聚合写（写模型）设计文档模板，落地 `docs/design/{聚合名}-aggregate-design-v{N}.md`。两份文档之一、**主文档**：横切章节（改动清单 / 测试 / 风险）在本份**统管整体需求**（含读侧与两侧存储落地）。

**§9 承载写聚合的关系表持久化**；**不再单列「时序（写路径）」章节**，写路径执行顺序在 §6 应用层设计体现。

| # | 章节 | 必选 |
| --- | --- | --- |
| 1 | 开始（聚合业务语义） | ✅ |
| 2 | 领域模型静态结构 | ✅ |
| 3 | 状态与行为设计 | ✅ |
| 4 | 业务规则设计 | ✅ |

> 规则：第 5/6/7 节按场景选填；其余 9 节恒必选。不适用节保留标题写「本次不适用，原因：……」。

## 3. 要点

- 结论先行（顶部引用块，含版本行与「替代 v(N-1) 章节」）。
- 修改类 §1 三层根因（直接 / 深层 / 本质，本质落职责 / 边界）。
- 静态结构给可直接编译骨架（真实包名 / 导入 / 构造）；枚举出入参用 `Integer` / 字符串基础类型。
- 状态类需求含允许矩阵；前置规则标注读旧快照 `old`（框架 `execute` 先领域逻辑后校验）。
- §6 应用层须写明一次写调用的执行顺序约束（原「时序」章节并入此处）。
- **§9 关系表**：表边界 = 聚合边界；聚合根主表 + 有独立身份的子实体子表（`TrackedList` 差量）+ 无身份值对象 JSON 列；无物理外键（仅 ID 引用）；必含 `version` 乐观锁列与审计列（`created_at/by`、`updated_at/by`）；逻辑外键只作过滤键、不映射进子实体。
- 横切 §8/§10/§11 **覆盖写 + 读整体**（含各自存储），不在读文档重复。
- 代码引用统一 `行号:相对路径`。

## 4. 自检（12 项）

开始业务语义 / 可编译骨架 / 允许矩阵 / 「不属于本设计」/ 旧快照 `old` / 应用层接口层齐全且含执行顺序 / 改动清单含整体路径+动作+说明且每步可编译 / **关系表=聚合边界+无物理外键+version 与审计列+子表 TrackedList+值对象 JSON 列** / 测试含确切码值标验收核心 / 风险含触发条件与应对且缺口标「不在本次范围」/ 附录 / 12 节编号标题一致。
