# BP 卡：聚合写设计文档模板（写模型）

> 源：`documentation/best-practices/design-doc-write-template.md` · 派生时间：2026-10-28 · 框架版本：2.1.0-SNAPSHOT

## 1. 定位

聚合写（写模型）设计文档模板，落地 `docs/design/{聚合名}-aggregate-design-v{N}.md`。两份文档之一、**主文档**：横切章节（改动清单 / 测试 / 风险）在本份**统管整体需求**（含读侧与两侧存储落地）。

**§7 承载写聚合的关系表持久化**；**不设「接口层设计（写）」章节**（HTTP / RPC 端点、Request DTO 不在范围）；写路径执行顺序在 §6 应用层设计体现，不单列「时序」章节。

## 2. 写法约定（产设计产物，不产设计说明书）

1. **只写设计，不写论证**：各节只产出产物（允许矩阵 / 规则表 / 事件表 / DDL / 骨架代码 / 清单 / 迁移图），不写「为什么这么设计」的推导、取舍比较、代价自辩。
2. **产物优先**：能用表 / 代码 / SQL / 图表达的不写散文；背景只给结论不给推导。
3. **读侧只列不展开**：横切章节覆盖读侧条目，但读侧设计细节指向读设计文档。
4. **演进根因与版本取舍不进本文**：三层根因、取舍写入 `aggregate-evolution-design` 或 v(N+1) 文档。
5. **框架符号不确定项集中登记**：`api-contract.md` 未登记的符号集中在风险节「框架签名不确定项」。
6. **结论与理由分离**；不要求顶部「结论先行」块。

## 3. 章节骨架（完整 11 节；选填节删除后顺延重编号）

| # | 章节 | 必选 |
| --- | --- | --- |
| 1 | 开始（聚合业务语义，不混技术实现） | ✅ |
| 2 | 领域模型静态结构（包布局 ~ 领域事件，可直接编译骨架） | ✅ |
| 3 | 状态与行为设计（操作清单 / 允许矩阵 / 状态迁移图 / 横切前置） | ✅ |
| 4 | 业务规则设计（规则容器骨架 + 组 A~D + 覆盖对照） | ✅ |
| 5 | 领域事件设计 | 视场景 |
| 6 | 应用层设计（Input / Factory / Updater / WriteService / 规则装配 + 执行顺序） | 视场景 |
| 7 | 聚合持久化（关系表）设计（DDL 优先） | ✅ |
| 8 | 改动清单与落地顺序（**统管整体**） | ✅ |
| 9 | 测试清单（**统管整体**） | ✅ |
| 10 | 风险与待确认事项（**统管整体**，含框架签名不确定项） | ✅ |
| 11 | 附录（参考资料；无则保留标题写「无」） | ✅ |

> 规则：第 5/6 节按场景选填；**选填节不适用时直接删除并顺延重编号**，保证编号连续，并在文档内声明删除原因；**不保留空标题占位**。**不设接口层章节**。

## 4. 关键约束

- 静态结构给可直接编译骨架（真实类名 / 构造）；枚举出入参用 `Integer` / 字符串基础类型。
- 状态类需求含允许矩阵 + 状态迁移图 + 横切前置；前置规则标注读旧快照 `old`（框架 `execute` 先领域逻辑后校验）。
- **§7 关系表**：表边界 = 聚合边界；聚合根主表 + 子实体子表（`TrackedList` 差量）+ 无身份值对象 JSON 列；无物理外键（仅 ID 引用）；必含 `version` 乐观锁列、审计列与软删列；**只给 DDL 与映射，不含建表论证**。
- 横切 §8/§9/§10 **覆盖写 + 读整体**（含各自存储），不在读文档重复。

## 5. 自检（12 项，不进产出文档）

业务语义开头 / 可编译骨架含包布局~领域事件 / 允许矩阵+状态迁移图+横切前置 / 旧快照 `old` / 应用层齐全含执行顺序 / **§7 DDL 含 version·审计·软删列且表边界=聚合边界、无物理外键、不含论证** / 改动清单覆盖写+读每步可编译 / 测试含确切码值标验收核心 / 风险含触发条件与应对且符号不确定项集中 / 附录 / 编号连续·声明删节·不设接口层 / **全文无论证性散文**。
