# BP 卡：代码注释规范（code-comment-specification）

> 源：`documentation/best-practices/code-comment-specification.md` · 派生时间：2026-10-17 · 框架版本：2.0.0

## 1. 本质

注释承载代码表达不了的业务信息，只写三类：**业务口径**（单位 / 币种 / 来源 / 取值域）、**边界约束**（状态迁移范围、写入时机）、**副作用事实**（记录操作、收集事件）。实现步骤、类型复述、示例代码、版本历史不属于注释。

通用要求（类级注释、公有方法注释）以仓库根 `AGENTS.md` 为准；本卡只补领域模型与应用服务的业务语义标准。

## 2. 适用范围与强度

| 层 | 元素 | 强度 | 要求 |
| --- | --- | --- | --- |
| 领域模型 | 聚合根 / 实体字段 | 命中 §3 清单时必填 | 业务口径 |
| 领域模型 | 公有业务方法 | 必填 | 意图 + 状态迁移范围 + 副作用 |
| 领域模型 | 公有构造方法 | 必填 | 创建语义、初始状态、副作用 |
| 应用服务 | `{Action}Input` 类 | 必填 | 三要素（§5.1） |
| 应用服务 | Input 字段 | 命中 §3 清单时必填 | 调用方传入口径 |

不覆盖：值对象、领域事件、`IParamObject` 参数对象、接口层 DTO（按 `AGENTS.md` 通用要求）。

## 3. 必写判定（非自解释才必填）

字段命中任一类必须写业务口径；名称已完整表达口径且不命中的可省略（如 `productId`）。

| # | 类别 | 判定信号 | 写清什么 |
| --- | --- | --- | --- |
| 1 | 金额 / 数量 | `Money` / `BigDecimal` / 数值 | 单位、币种、含税与优惠口径 |
| 2 | 时间 | `LocalDateTime` / `Instant` / 时间戳 | 业务时间还是系统时间、由谁写入 |
| 3 | 编码 / 状态 | 命名含 `code` / `status` / `type` | 业务来源（如快递公司编码）、取值域 |
| 4 | 派生字段 | 由其他字段计算得出 | 由谁派生、何时刷新 |
| 5 | 外部回填 | 外部系统返回后写入 | 来源系统、写入时机 |
| 6 | 非直观命名 | 名称歧义或业务专有词 | 业务含义、与易混淆字段的区别 |

**一致性硬约束**：同一类内不能一半字段有注释、一半没有；命中清单的必须写，"可省"不等于"补一句翻译"。判定法：把字段名交给不熟悉该业务的人，说不出业务口径就必须注释。

## 4. 领域模型层规则

### 4.1 字段

- 位置：字段上方 Javadoc。
- 禁止：同义反复（`/** 商品 ID */`）、持久化细节（列名 / 长度）、类型复述。

```java
/**
 * 订单生命周期状态：仅在创建 / 取消 / 关闭 / 完成等生命周期动作中显式赋值。
 */
private OrderStatus status;

/**
 * 库存预占单号：外部库存系统预占成功后的事实回填。
 */
private String reserveNo;

/**
 * 订单项小计，由 price 与 quantity 相乘派生，随数量或单价变更同步刷新。
 */
private Money subtotal;
```

### 4.2 公有业务方法

必须回答三件事：做什么；影响 / 不影响哪些状态；是否 `recordOperation` / `collectEvent`。`@param` 只写业务口径，不写 `@param quantity 数量` 这类复述。

```java
/**
 * 标记订单已发货并记录物流信息，并发布订单发货事件。
 * 只推进物流状态，不改动支付状态与订单生命周期状态。
 *
 * @param logisticsInfo 物流信息
 */
public void ship(LogisticsInfo logisticsInfo) {
    // ...
}
```

业务方法遵循"纯赋值"原则，注释不写守卫条件、字段组装、格式转换。

### 4.3 构造方法

- 业务构造：写创建语义、初始状态、副作用（`recordOperation` / `collectEvent`）。
- `protected` 无参构造：写"仅供持久化框架重建，空实现"。

## 5. 应用服务层规则

### 5.1 Input 类三要素

1. 业务语义（哪个用例的入参）。
2. 边界：与协议无关、应用层自有扁平结构、不引用领域值对象。
3. 转换归属：由哪个 `Factory` / `Updater` 转换为领域对象。

### 5.2 Input 字段

写调用方必须知道的口径，不写转换后的领域结构：

| 场景 | 要求 |
| --- | --- |
| 金额 | 币种、单价还是小计、是否已扣优惠 |
| 时间 | 业务时间还是系统时间、时区 |
| 编码型 | 业务来源（如 `companyCode` 为快递公司编码） |
| 组合字段 | 多字段如何共同构成领域值对象（金额 + 币种 → `Money`） |

## 6. 形式规范

| 项 | 规则 |
| --- | --- |
| 位置 | 字段 / 方法上方，禁止行尾注释 |
| 单行与多行 | 单句 `/** ... */`；多句或带边界说明用多行块；同类内一致 |
| 分段 | 多段用 `<p>` |
| 元信息 | 作者标注按团队约定，不做要求；不写 `@version` / `@since` / 日期 / 需求号 |
| 参数 | `@param` 只写业务口径，无额外口径时省略 |
| 术语 / 语言 | 与代码标识符、领域术语一致；中文标点，句末句号 |

## 7. 常见反模式

| 反模式 | 问题 | 正确做法 |
| --- | --- | --- |
| 翻译式注释 | 与代码重复，零信息量 | 自解释则省，否则写口径 |
| 命中金额 / 时间 / 编码类不写口径 | 调用方靠猜 | 按 §3 补口径 |
| 注释代替命名 | 用长注释掩盖糟糕命名 | 先改命名 |
| 过期注释 | 行为已改、注释未改 | 与代码同改，不一致视为缺陷 |
| 注释写实现步骤 / 伪代码 | 重复且易失效 | 只写意图、边界、副作用 |
| 业务方法漏状态边界 | 相邻状态被误改 | 写清推进什么、不推进什么 |
| `@param` 复述参数名 | 无信息量 | 省略或补口径 |
| 注释放示例代码 | 示例失真无人维护 | 示例放文档 |
