# 聚合识别设计原则（KB 卡）

> 从「一份需求」识别「一组聚合候选及其边界」。战略建模步骤，用于全新需求从 0 识别，也用于迭代中「要不要新增聚合」的判断。识别结果喂给 `aggregate-design` 并落《聚合设计文档标准》。

## 识别四步（事件风暴）
1. **列事件**：过去式业务事实（「订单已支付」），每事件归属一个潜在聚合；同动作下事件密集且需强一致的归同候选。
2. **提炼不变性**：追问「哪些规则必须一次事务内一致」→ 强一致归同聚合；最终一致走事件。
3. **定边界**：A 的不变性依赖 B 当前态且需同事务 → 同聚合；A 只关心 B「发生了什么」→ 跨聚合（B 发事件、A 订阅）。
4. **定粒度（小聚合）**：引入不需同锁的实体→拆；跨聚合只持 ID（约束 13）；子实体随父存在且无独立访问→同聚合子表，否则独立聚合。

## 边界判据清单（每个候选必须答出）
- 聚合根是谁、为何是它；
- 包含哪些实体 / 值对象；
- **不归本聚合管什么**（防边界蔓延）；
- 维护哪些核心不变量；
- 与他聚合是强一致还是最终一致。

## 迭代「加聚合」判定
1. 新能力不变量与既有聚合同事务强一致 → 扩到该聚合（走演进设计）。
2. 否则有独立生命周期 / 独立访问 → **新增独立聚合**。
3. 仅是只读视图 → 走投影读模型，不增聚合。
> 法则：加进既有聚合会致膨胀 / 并发冲突上升时，倾向独立成聚合，跨聚合以事件 / ID 协作。

## 反模式
| 误判 | 纠偏 |
| --- | --- |
| 一个聚合包整个领域 | 按不变性切小聚合 |
| 跨聚合持对象引用 | 只持 ID（约束 13） |
| 最终一致当强一致硬塞同聚合 | 跨聚合走领域事件 |
| 无身份值对象建子表 | 并入父表 JSON |
| 子实体被他聚合独立访问却塞同聚合 | 提为独立聚合 |
