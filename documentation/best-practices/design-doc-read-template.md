# 投影读设计文档模板（读模型）

> 本模板用于产出「投影读（读模型）」设计文档，落地 `docs/design/{聚合名}-projection-read-design-v{N}.md`。
> 它是 **ddd-design-doc** 一次需求产出的**两份文档之一**（另见 聚合写模板）。
> 本份**只聚焦读模型设计及其投影持久化**（ES 索引 / Redis 结构），**不含**独立命名的「改动清单 / 测试 / 风险」章节——这些横切内容由聚合写文档统管。允许在相应设计章节内用段落描述读路径，但不立横切章节标题。
> **下笔前先读 §1 写法约定**；章节骨架见 §2，可复制的完整模板见 §3，作者 / 评审自查见 §4。

## 1. 写法约定（先读）

本模板产出的是**设计产物**，不是设计说明书。写作时遵守：

1. **只写设计，不写论证**：各节只产出产物（mapping / 结构 / DTO / Query 条件族 / 常量 / 路径），**不写「为什么这么设计」的推导、选型比较、代价自辩**。
2. **产物优先**：能用表 / 代码 / mapping / 结构描述的不写散文；确需交代背景时**只给结论**，不给推导。
3. **写侧只列不展开**：聚合写侧的设计、规则、不变量、表结构一律**指向聚合写文档**，不在本文展开；本文只给读模型与其投影存储。
4. **演进根因与版本取舍不进本文**：三层根因、方案取舍、代价记录写入 [`aggregate-evolution-design`](/best-practices/aggregate-evolution-design) 或 v(N+1) 文档，本文不设该节。
5. **框架符号不确定项交写文档统管**：本文不设风险章节，`api-contract.md` 未登记的符号写入聚合写文档的「框架签名不确定项」，不在本文分散说明。
6. **结论与理由分离**：散文里若同时含结论与理由，删理由、留结论。**不写顶部「结论先行」块**。
7. **框架机制不重复**：投影基类 API、ES 配置、事件订阅等属框架机制，本文只引用不展开，详见 §5 框架机制参考。
8. **不设「接口层设计（读）」章节**：HTTP / RPC 端点、Response DTO 不在本文范围内。

## 2. 章节骨架（完整 6 节；选填节删除后顺延重编号）

| # | 章节 | 必选 | 回答的问题 |
| --- | --- | --- | --- |
| 1 | 概述与背景 | ✅ | 这份读模型解决什么查询需求；来源事件 / 聚合；存储选型（ES / Redis / 双副本） |
| 2 | 投影整体设计 | ✅ | 四角色（投影器 / 源 / 裁剪器 / 读服务）、副本维度、领域契约 |
| 3 | 读模型静态结构 | ✅ | 投影 DTO、条件族 `Query`、副本常量；枚举降级为基础类型 |
| 4 | 投影持久化（ES / Redis）设计 | 视场景 | ES 索引 mapping / `REPLICA_ID` / 分片副本 / 版本语义；Redis `REPLICA_KEY` / value 自带 `version` / TTL / 仅 ById 族；其他存储 |
| 5 | 投影构建与同步路径 | 视场景 | 写路径触发 `sync`、订阅者、materialize / purge / readVersion / rebuild |
| 6 | 查询设计 | ✅ | 查询族分派、读服务两跳、Redis/ES 选择、分页 / 排序 |

> 规则：
> - 第 4 / 5 节按场景选填；其余 4 节（1 / 2 / 3 / 6）恒必选。**不设接口层章节、不设改动清单 / 测试 / 风险章节**（后三者由聚合写文档统管）。
> - **选填节不适用时直接删除，并将其后章节顺延重编号**，保证编号连续；同时在文档内声明「本次删除了第 N 节（原因：……）」。**不保留空标题占位**（会造成编号缺口）。§4 内不适用的存储子节（ES / Redis / 其他）同样直接删除。
> - 副本存储是「构建」与「查询」共同的 substrate，故先定义 §4 存储结构，再讲 §5 如何 materialize、§6 如何查询。

```markdown
## 1. 概述与背景
{查询需求；来源事件 / 聚合；存储选型（ES / Redis / 双副本）}

## 2. 投影整体设计
### 2.1 四角色（每个读模型一套）
{投影器 Projector / 源 Source / 裁剪器 Reducer / 读服务 ReadService}
### 2.2 副本维度
{副本维度；领域契约 I{Agg}Projection / I{Agg}{Store}Source}

## 3. 读模型静态结构
### 3.1 投影 DTO（@Data，枚举降级为基础类型）
### 3.2 条件族 Query（sealed + record，基础类型承载）
### 3.3 副本常量
{枚举降级为基础类型（int code + String name 双写）；金额 BigDecimal 原样承载}

## 4. 投影持久化（ES / Redis）设计
### 4.1 ES 索引设计
{索引 mapping；REPLICA_ID；分片 / 副本策略；_version / External 版本；支撑的查询族（与 §6 呼应）}
### 4.2 Redis 结构设计
{REPLICA_KEY 设计；value 结构（自带 version 字段）；TTL；仅 ById 族}
### 4.3 其他存储
{如对象存储 / 其他 KV；不适用则删除本子节}
{只给结构与常量，不写「为什么这么选型」的论证}

## 5. 投影构建与同步路径
{写路径触发 sync；订阅者 handleEvent → findById → 源.sync}
{materialize / purge / readVersion / rebuild；External 版本语义}

## 6. 查询设计
{查询族分派；读服务两跳（查全量 → getReducer 裁剪）；Redis/ES 选择}
{分页 / 排序；不回源聚合根；totalCount/nextCursor 取裁剪前}
```

## 4. 符合性自检（作者 / 评审用，**不进产出文档**）

> 本章仅供写作与评审自查使用，**产出文档中不要包含本章**（避免自检项与章节号随文漂移、项数与实际不符）。

| # | 检查项 | 不满足的后果 |
| --- | --- | --- |
| 1 | §1 概述说清查询需求、来源事件 / 聚合、存储选型（**不写选型理由**） | 评审方向不明 |
| 2 | 投影整体设计含四角色与领域契约（I{Agg}Projection / I{Agg}{Store}Source） | 端口 / 实现错位 |
| 3 | 读模型枚举降级为基础类型，金额 BigDecimal 原样 | 查询 / 裁剪换算散落、类型错配 |
| 4 | §4 投影持久化**只给结构产物**（ES mapping / `REPLICA_ID`、Redis `REPLICA_KEY` / 自带 version / TTL / 仅 ById），与 §6 查询族呼应，**不含选型论证** | 副本结构与查询错位 |
| 5 | 源只 extends 真实支撑的查询族（Redis 仅 ById） | 编译期能力误用 |
| 6 | 读服务两跳、不回源聚合根、totalCount/nextCursor 取裁剪前 | 读路径错误 |
| 7 | 章节编号**连续**；删除的选填节已在文档内声明（**不要求恒为 6 节**）；**不设接口层章节** | 编号缺口 / 规格不统一 |
| 8 | **全文无「为什么这么设计」的论证性散文**（选型、代价、推导不进正文） | 文档冗长、结论被稀释 |
