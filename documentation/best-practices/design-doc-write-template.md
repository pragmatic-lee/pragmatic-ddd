# 聚合写设计文档模板（写模型）

> 本模板用于产出「聚合写（写模型）」设计文档，落地 `docs/design/{聚合名}-aggregate-design-v{N}.md`。
> 它是 **ddd-design-doc** 一次需求产出的**两份文档之一**（另见 投影读模板），且为**主文档**：横切章节（改动清单 / 测试 / 风险）在本份**统管整体需求**（含读侧与两侧存储的落地）。
> 通用规则（版本化、命名、枚举基础类型、防幻觉）见 [`design-doc-template.md`](./design-doc-template.md)。本模板不要求顶部「结论先行」块，也不再单列「概述与背景」「聚合边界与职责」——聚合的业务语义统一收到 §1「开始」。
> **下笔前先读 §1 写法约定**；章节骨架见 §2，可复制的完整模板见 §3，作者 / 评审自查见 §4。

## 1. 写法约定（先读）

本模板产出的是**设计产物**，不是设计说明书。写作时遵守：

1. **只写设计，不写论证**：各节只产出产物（允许矩阵 / 规则表 / 事件表 / DDL / 骨架代码 / 清单 / 迁移图），**不写「为什么这么设计」的推导、取舍比较、代价自辩**。
2. **产物优先**：能用表 / 代码 / SQL / 图表达的不写散文；确需交代背景时**只给结论**（如「阻断式前置，不级联」），不给推导。
3. **读侧只列不展开**：横切章节（改动清单 / 测试 / 风险）要**覆盖**读侧条目，但读侧的设计、存储与投影细节一律**指向读设计文档**，不在本文展开。
4. **演进根因与版本取舍不进本文**：三层根因、v0 vs v1 取舍、代价记录写入 [`aggregate-evolution-design`](/best-practices/aggregate-evolution-design) 或 v(N+1) 文档，本文不设该节。
5. **框架符号不确定项集中登记**：`api-contract.md` 未登记的符号**集中**记在风险节（如「框架签名不确定项」），不在骨架章节分散说明。
6. **结论与理由分离**：散文里若同时含结论与理由，删理由、留结论。
7. **框架机制不重复**：投递通道（Outbox / Relay）、事件管理器等属框架机制，本文只引用不展开，详见 §5 框架机制参考。
8. **不设「接口层设计（写）」章节**：HTTP / RPC 端点、Request DTO 不在聚合写设计文档范围内。

## 2. 章节骨架（完整 11 节；选填节删除后顺延重编号）

| # | 章节 | 必选 | 回答的问题 |
| --- | --- | --- | --- |
| 1 | 开始（聚合业务语义） | ✅ | 这个聚合在业务上是什么、解决什么业务问题、核心职责是什么（仅业务语义，不展开技术实现） |
| 2 | 领域模型静态结构 | ✅ | 聚合根 / 值对象 / 标识符骨架（可直接编译）；枚举出入参用基础类型 |
| 3 | 状态与行为设计 | ✅ | 操作 / 命令、状态机与允许矩阵 |
| 4 | 业务规则设计 | ✅ | 不变量表达、何时校验（当前态 / 旧快照 `old`） |
| 5 | 领域事件设计 | 视场景 | 事件清单与载荷、订阅者、投影影响（声明式） |
| 6 | 应用层设计 | 视场景 | Input、Updater、WriteService 入口与调用顺序 |
| 7 | 聚合持久化（关系表）设计 | ✅ | **DDL 优先**：表结构、字段、索引；表边界 = 聚合边界；`version` / 审计列；无物理外键；映射与仓储 |
| 8 | 改动清单与落地顺序 | ✅ | **统管整体**：写 + 读（含各自存储）的确切文件路径 + 动作 + 说明 + 落地顺序 |
| 9 | 测试清单 | ✅ | **统管整体**：写 / 读（含存储）的用例与确切消息码 / 枚举值，标验收核心 |
| 10 | 风险与待确认事项 | ✅ | **统管整体**：触发条件 + 应对，缺口标「不在本次范围」；框架符号不确定项集中登记 |
| 11 | 附录（参考资料） | ✅ | 列出引用的框架机制卡 / 外部资料；无则保留标题写「无」 |

> 规则：
> - 第 5 / 6 节按场景选填；其余 9 节恒必选。**不设接口层章节**。
> - **选填节不适用时直接删除，并将其后章节顺延重编号**，保证编号连续；同时在文档内声明「本次删除了第 N 节（原因：……）」。**不保留空标题占位**（会造成编号缺口）。
> - 「统管整体」= 覆盖写 + 读（含各自存储）的条目；读侧细节指向读设计文档，不在本文展开。
> - 写路径的执行顺序在 §6 应用层设计中体现，**不再单列「时序（写路径）」章节**。

## 4. 符合性自检（作者 / 评审用，**不进产出文档**）

> 本章仅供写作与评审自查使用，**产出文档中不要包含本章**（避免自检项与章节号随文漂移、项数与实际不符）。

| # | 检查项 | 不满足的后果 |
| --- | --- | --- |
| 1 | §1「开始」从业务语义说明聚合的定位与核心职责（不混入技术实现） | 评审者不了解业务上下文 |
| 2 | 静态结构给出可直接编译的骨架（真实类名 / 构造），子章节覆盖包布局 ~ 领域事件 | 实现者无法落地 |
| 3 | 状态类需求含允许矩阵或等价穷举表，并含状态迁移图与横切前置 | 遗漏状态组合 |
| 4 | 前置类规则明确标注读旧快照 `old` | 规则写对但拦不住 |
| 5 | 应用层齐全（Input / Factory / Updater / WriteService / 规则装配），含一次写调用的执行顺序约束 | 调用顺序错乱 |
| 6 | §7 关系表 DDL 含 `version` / 审计 / 软删列，表边界 = 聚合边界，无物理外键；**只给 DDL 与映射，不含建表论证** | 跨聚合外键、缺乐观锁或混入论证 |
| 7 | 改动清单含确切文件路径 + 动作 + 说明（**覆盖写 + 读，含各自存储**），并给出落地顺序、每步可编译 | 找不到文件 / 中途编译失败 |
| 8 | 测试清单含确切消息码 / 枚举值，标出验收核心（**覆盖整体**） | 无法判断实现正确 |
| 9 | 风险含触发条件与应对，缺口标「不在本次范围」；框架符号不确定项**集中**登记在一处 | 踩坑且范围失控 |
| 10 | 附录列出参考资料，或无则保留标题 | 引用不可追溯 |
| 11 | 章节编号**连续**；删除的选填节已在文档内声明（**不要求恒为 11 节**）；**不设接口层章节** | 编号缺口 / 规格不统一 |
| 12 | **全文无「为什么这么设计」的论证性散文**（取舍、代价、推导不进正文） | 文档冗长、结论被稀释 |
