# 聚合写设计文档模板（写模型）

> 本模板用于产出「聚合写（写模型）」设计文档，落地 `docs/design/{聚合名}-aggregate-design-v{N}.md`。
> 它是 **ddd-design-doc** 一次需求产出的**三份文档之一**（另见 投影读模板 / 持久化模板），且为**主文档**：横切章节（改动清单 / 测试 / 风险 / 时序）在本份**统管整体需求**（含读侧与持久化侧的落地）。
> 通用规则（版本化、命名、枚举基础类型、防幻觉）见 [`design-doc-template.md`](./design-doc-template.md)。本模板不要求顶部「结论先行」块，也不再单列「概述与背景」「聚合边界与职责」——聚合的业务语义统一收到 §1「开始」。

## 1. 章节骨架（12 节，编号与标题恒定）

| # | 章节 | 必选 | 回答的问题 |
| --- | --- | --- | --- |
| 1 | 开始（聚合业务语义） | ✅ | 这个聚合在业务上是什么、解决什么业务问题、核心职责是什么（仅业务语义，不展开技术实现） |
| 2 | 领域模型静态结构 | ✅ | 聚合根 / 值对象 / 标识符骨架（可直接编译）；枚举出入参用基础类型 |
| 3 | 状态与行为设计 | ✅ | 操作 / 命令、状态机与允许矩阵、边界澄清 |
| 4 | 业务规则设计 | ✅ | 不变量表达、何时校验（当前态 / 旧快照 `old`） |
| 5 | 领域事件设计 | 视场景 | 发出哪些事件、载荷、订阅者、投影影响（声明式） |
| 6 | 应用层设计 | 视场景 | Input、Updater、WriteService 入口与调用顺序 |
| 7 | 接口层设计（写） | 视场景 | 写侧 HTTP / RPC、路径、Request DTO |
| 8 | 时序（写路径） | ✅ | 一次写调用的完整执行路径 + 顺序约束 |
| 9 | 改动清单与落地顺序 | ✅ | **统管整体**：写 + 读 + 持久化的确切文件路径 + 动作 + 说明 + 落地顺序 |
| 10 | 测试清单 | ✅ | **统管整体**：写 / 读 / 持久化的用例与确切消息码 / 枚举值，标验收核心 |
| 11 | 风险与待确认事项 | ✅ | **统管整体**：触发条件 + 应对，缺口标「不在本次范围」 |
| 12 | 附录（参考资料） | ✅ | 列出引用的框架机制卡 / 外部资料；无则保留标题写「无」 |

> 规则：第 5 / 6 / 7 节按场景选填；其余 9 节恒必选。某节确实不适用时**保留标题并写明「本次不适用，原因：……」**，不要删除。

## 3. 符合性自检（12 项）

| # | 检查项 | 不满足的后果 |
| --- | --- | --- |
| 1 | §1「开始」从业务语义说明聚合的定位与核心职责（不混入技术实现） | 评审者不了解业务上下文 |
| 2 | 静态结构给出可直接编译的骨架（真实类名 / 构造） | 实现者无法落地 |
| 3 | 状态类需求含允许矩阵或等价穷举表 | 遗漏状态组合 |
| 4 | 明确写出「不属于本设计」的边界 | 范围失控 |
| 5 | 前置类规则明确标注读旧快照 `old` | 规则写对但拦不住 |
| 6 | 应用层 / 接口层（写侧）齐全，零改动写明理由 | 误判为遗漏 |
| 7 | 改动清单含确切文件路径 + 动作 + 说明（**覆盖写 + 读 + 持久化**） | 找不到文件 |
| 8 | 给出落地顺序且每步可编译 | 中途编译失败 |
| 9 | 测试清单含确切消息码 / 枚举值，标出验收核心（**覆盖整体**） | 无法判断实现正确 |
| 10 | 风险含触发条件与应对，缺口标「不在本次范围」（**覆盖整体**） | 踩坑且范围失控 |
| 11 | 附录列出参考资料，或无则保留标题 | 引用不可追溯 |
| 12 | 章节编号与标题与本模板一致（固定 12 节） | 文档规格不统一 |
