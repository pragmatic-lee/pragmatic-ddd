# 聚合设计文档标准（三份拆分 · 总说明与索引）

> 本文是 **ddd-design-doc** 能力产出设计文档的**总说明与索引**。
> 原「单一 13 节文档」已演进为**三份独立文档**（写 / 读 / 持久化），对应 CQRS 的三个关注点。本文只定义**通用规则与三份的协同关系**，具体骨架见三份模板。

## 1. 为什么拆三份

一个聚合的设计天然分成三个关注点，强行塞进一份文档会互相挤占、且 ES 索引 / Redis 结构根本没有章节承载：

- **聚合写（写模型）**：聚合根、实体 / 值对象、状态机、业务规则、领域事件——命令如何改变聚合。
- **投影读（读模型）**：异构存储副本怎么建、怎么查——与写模型装配解耦的独立读视图。
- **持久化（存储）**：关系表 DDL / 映射 / 仓储，以及 ES 索引结构、Redis 结构。

三份各自成篇，便于分头评审、独立落地。

## 2. 三份文档与定位

| 文档 | 定位 | 落盘命名（同一需求共用 `v{N}`） | 统管横切？ |
| --- | --- | --- | --- |
| **① 聚合写**（主文档） | 写模型设计 | `docs/design/{聚合名}-aggregate-design-v{N}.md` | ✅ 统管整体（改动清单 / 测试 / 风险 / 时序） |
| **② 投影读**（专项） | 读模型设计 | `docs/design/{聚合名}-projection-read-design-v{N}.md` | ❌ 只聚焦自身 |
| **③ 持久化**（专项） | 存储设计 | `docs/design/{聚合名}-persistence-design-v{N}.md` | ❌ 只聚焦自身 |

## 3. 通用规则（三份共用）

- **结论先行**：每份文档顶部引用块给出「选什么方案 + 为什么」；附「本文仅为设计文档，未改动任何代码」。
- **版本化**：同一需求的三份文档共用同一 `v{N}`；文件名与结论先行块均含版本。
- **枚举基础类型**：出入参 / 查询条件 / 应用层 Input 的枚举用 `Integer` / 字符串；投影读模型枚举同样转为基础类型（见 [`enum-value`](/best-practices/enum-value)）。
- **防幻觉红线**：边界 / 识别 / 演进判据以 KB 卡与模板为权威；拿不准先 Read 对应卡，缺符号向用户提问；KB 是产物不是源，源约定变更先回写 `documentation/best-practices/` 再重派生。
- **横切统管**：改动清单 / 测试 / 风险 / 时序**只在聚合写文档**出现，且覆盖**整体需求**（写 + 读 + 持久化），一份主文档驱动整体落地。
- **各自独立成篇**：三份不强关联、不强制交叉引用（写文档事件表的「投影影响」列仍写事实，但不强链读文档）。
- **不适用节保留标题**：某节确实不适用时保留标题并写明「本次不适用，原因：……」，不删节。

## 6. 符合性自检（总览）

- 三份文档各通过其对应模板的自检清单（写 12 项 / 读 6 项 / 持久化 5 项）。
- 三份版本号一致，且各自带结论先行块。
- 横切章节（改动清单 / 测试 / 风险 / 时序）仅在写文档出现，覆盖整体需求。
